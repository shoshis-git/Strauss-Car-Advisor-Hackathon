# יועץ הרכב של שטראוס

יועץ שיחתי לעובדים שמשווה בין רכב החברה הנוכחי לבין חלופה (רכב אחר מהקטלוג או ויתור על רכב) ומראה בשקלים מה קורה לשכר הנטו החודשי.

העובד מתאר את מצבו בשפה חופשית, או מעלה תלוש שכר. היועץ אוסף את הנתונים החסרים, בודק זכאות לפי נוהל החברה ומחזיר השוואה מפורטת. כשחסר נתון שאי אפשר לנחש (למשל גובה השתתפות רשמי), השאלה עוברת לנציג/ת שכר, והשיחה ממתינה עד שמתקבלת תשובה.

## ניסיון מהיר

**כתובת האתר:** `https://strauss-car-advisor-hackathon.vercel.app`



### כניסת עובד

| חשבון דמו | לוחצים על שם עובד בקטע "חשבונות דמו להדגמה" | כניסה מיידית. העיסוק, הקבוצה, השכר, ההפרשות והרכב הנוכחי נטענים מראש, והבוט שואל רק מה לבדוק |

### כניסת נציג

לשונית **"נציג/ה"** בראש המסך, ובה מקלידים את מפתח הנציג.
- **בענן:** המפתח נמסר בנפרד, בטופס ההגשה. הוא לא כתוב כאן, כי ה-README ציבורי. מי שמנהל את השרת מוצא אותו ב-Render: השירות ← **Environment** ← `REP_API_KEY`.
- **מקומית:** הערך של `REP_API_KEY` בקובץ `.env`.

### תסריט מומלץ (בערך 3 דקות)

1. **שאלה ותשובה:** נכנסים כ**נועה לוי** וכותבים "אני רוצה לעבור לאטו 3".
   - מתקבל ‎+661 ₪, עם פירוט ועם הערה שההשתתפות (300 ₪) נלקחה מקטלוג החברה.
   - מתחת להשוואה מופיע הכרטיס "יש 6 אפשרויות שמשאירות לך יותר נטו". לחיצה על שורה מחשבת אותה.
2. **העברה לנציג:** כותבים "אצלי סוכם אחרת ואני לא יודעת כמה".
   - השיחה מוקפאת, ובינתיים מוצג הנטו של היום.
   - בלשונית הנציג עונים 350. ההשוואה מתעדכנת לבד ל-‎+611.
3. **בקשה שאינה מותרת:** יוצאים ונכנסים כאורח. כותבים "אני מפתח תוכנה ורוצה טסלה מודל 3".
   - הבוט מסרב מיד, מסביר שהרכב בקבוצה מעל הקבוצה של העובד, ומציע חלופות מותרות.
4. **שאלה מחוץ לתחום:** שואלים "מה מדרגות המס של 2026?".
   - הבוט עונה שאין לו את המידע הזה, ושהחישוב מבוסס על לוחות 2025.

## עקרונות

- **המספרים לא מגיעים ממודל השפה.** כל החישובים נעשים במנוע דטרמיניסטי (`backend/engine`). מודל השפה רק מנהל את השיחה וקורא לכלים.
- **שום כלל עסקי לא כתוב בקוד.** תקציבים, סדר קבוצות, מסלול משפחה, ויתור, שיטת הנטו וכדומה נקראים מ-`data/rules.json` ומ-`data/challenge_data.xlsx`. החלפת הקבצים מעדכנת את ההתנהגות, וגם את מה שהיועץ מסביר לעובד.
- **שווי השימוש** נלקח מהמאגר הרשמי של רשות המסים לשנת 2026 (בערך 78 אלף רשומות). החיפוש נעשה לפי המפתח הרשמי: שנת מס, שנת רישום, סוג רכב, תוצר ודגם.
- **פרטיות.** תלוש השכר נקרא בזיכרון ולא נשמר. לפני שטקסט כלשהו נשלח למודל, מוסתרים ממנו פרטים מזהים: ת"ז, חשבון בנק, כתובת, טלפון, דוא"ל ושם. נכנסים למצב השיחה רק ערכים שהעובד אישר.

## הרצה מקומית

דרישות: Python 3.12 ו-Node.js 20 ומעלה.

### Backend

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows   (Linux/macOS: source .venv/bin/activate)
pip install -r requirements-dev.txt
copy .env.example .env            # ראו "מה ממלאים ב-.env" למטה
python -m backend.data_loader.build_data   # אופציונלי: נבנה גם לבד בהפעלה הראשונה
uvicorn backend.main:app --reload --port 8000
```

**מה ממלאים ב-`.env`:**

| משתנה | חובה? | ערך |
|---|---|---|
| `LLM_PROVIDER`, `LLM_MODEL`, `LLM_API_KEY` | כן | למשל `gemini`, `gemini-3.8-flash` ומפתח מ-Google AI Studio |
| `SECRET_KEY` | מומלץ | מחרוזת אקראית ארוכה (פקודה למטה). בלעדיו, כל הפעלה מחדש מנתקת את כולם |
| `REP_API_KEY` | בשביל מסך הנציג | מחרוזת אקראית ארוכה. זה המפתח שמקלידים בלשונית הנציג |
| `LLM_PROVIDER_2` (+ `_MODEL_2`, `_API_KEY_2`) | מומלץ | ספק **אחר** לגיבוי, למשל groq או openrouter. גיבוי של אותו ספק לא עוזר כשהספק עצמו עמוס |

יצירת ערך אקראי ל-`SECRET_KEY` ול-`REP_API_KEY`:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

אחרי ההפעלה נכנסים ב-http://localhost:5173 (אחרי הפעלת ה-frontend, למטה) עם חשבון דמו, כמו בקטע "ניסיון מהיר".

- תיעוד API אינטראקטיבי: http://localhost:8000/docs
- בדיקת חיבור למודל השפה (מפתחות לא מודפסים): `python -m backend.agent.llm_check`
- אחרי שינוי ב-`.env` צריך להפעיל את השרת מחדש. `--reload` עוקב רק אחרי קבצי `.py`.

### Frontend

```bash
cd frontend
npm install
npm run dev                       # http://localhost:5173
```

כתובת ה-backend נקבעת לפי `VITE_API_BASE`, וברירת המחדל היא `http://localhost:8000`. כדי לשנות אותה מעתיקים את `frontend/.env.example` ל-`frontend/.env.local`.

אם מופיעה ההודעה "השרת אינו זמין":
- **ה-backend לא רץ:** מפעילים אותו בפורט 8000.
- **הכתובת בהודעה אינה `localhost:8000`:** משתנה `VITE_API_BASE` נשאר במסוף. מוחקים אותו (`Remove-Item Env:VITE_API_BASE` ב-PowerShell) ומפעילים מחדש את `npm run dev`.

## משתני סביבה (backend)

הרשימה המלאה, עם הסברים, נמצאת ב-[.env.example](.env.example).

| משתנה | תפקיד |
|---|---|
| `LLM_PROVIDER` / `LLM_MODEL` / `LLM_API_KEY` | ספק המודל, שם המודל ומפתח. `rules` = בלי LLM (לבדיקות בלבד) |
| `LLM_BASE_URL` | כתובת חלופית; חובה עבור `openai_compatible` |
| `LLM_PROVIDER_2` ... `_5` | ספקים לגיבוי: אם אחד נכשל (מכסה, קרדיט, תקלה), הבא בתור עונה |
| `LLM_FALLBACK` | `none` (ברירת מחדל): העובד רואה את סיבת התקלה. `rules`: המוח הדטרמיניסטי עונה במקום המודל |
| `SECRET_KEY` | חתימת טוקני הכניסה של העובדים. אם הוא ריק, נוצר מפתח אקראי בכל הפעלה, וכולם צריכים להיכנס מחדש. החלפה שלו מנתקת את כולם |
| `REP_API_KEY` | מפתח מסך הנציג (נשלח בכותרת `X-Rep-Token`). אם הוא ריק, מסך הנציג סגור |
| `PAYSLIP_VISION` | `on`: תלוש בלי טקסט קריא (סריקה) נקרא מתמונת העמוד על ידי המודל |
| `DATABASE_URL` | אם הוא ריק, השיחות נשמרות ב-SQLite מקומית. בייצור: ה-URI של ה-Transaction pooler ב-Supabase |
| `CORS_ORIGINS` | כתובות דפדפן נוספות שמותר להן לפנות לשרת, מופרדות בפסיקים. localhost תמיד מותר |
| `API_DOCS` | `0` מכבה את `/docs` (מומלץ בייצור) |
| `STRAUSS_DATA_DIR` | תיקיית נתונים חלופית (למשל נתוני פיילוט אמיתיים) |

## בדיקות

```bash
pytest                            # backend: נתונים, מחשבון, סוכן, API, כניסה ואבטחה, תלושים
cd frontend && npm test           # frontend: Vitest + Testing Library
```

**בדיקת האינטגרציה של ה-frontend** (`App.integration.test.tsx`) מפעילה את האפליקציה מול שרת אמיתי. אם אין שרת זמין, היא מדלגת על עצמה. כדי להריץ אותה, מפעילים שרת במצב בלי מודל שפה, עם מפתח נציג קבוע:

```powershell
# חלון 1 - השרת
$env:LLM_PROVIDER="rules"; $env:REP_API_KEY="e2e-rep-key-0123456789"; uvicorn backend.main:app --port 8000
# חלון 2 - הבדיקות
cd frontend; npm test
```

- הבדיקות של ה-backend רצות offline עם `RuleBasedLLM`, שמדבר באותו פרוטוקול קריאה לכלים כמו מודל אמיתי.
- המחשבון נבדק מול חישובי הייחוס של 6 העובדים לדוגמה באקסל, בכל 9 העמודות.
- בדיקה מול מודל אמיתי רצה רק כש-`LLM_PROVIDER` מוגדר.
- בדיקה מול Postgres אמיתי רצה רק כש-`TEST_DATABASE_URL` מוגדר.

## סיכום: מה עובד, מגבלות, מה נדרש לפיילוט

### מה עובד
- **שיחה בעברית:** הבוט שואל רק מה שחסר, בשני סבבים לכל היותר. עובד מזוהה נשאל רק על החלופה.
- **הכללים:** השוואה לרכב אחר, לרכב חשמלי (החזר חשמל מגולם של 250 ₪ נטו), למסלול ברוכת ילדים ולוויתור לפי עיסוק. בדיקת זכאות מיידית, עם חלופות מותרות כשהבקשה אינה אפשרית.
- **החישוב:** שווי שימוש ממאגר רשות המסים לפי המפתח הרשמי. מנוע החישוב תואם את 6 חישובי הייחוס של האתגר בכל העמודות.
- **"כל האפשרויות שלי":** הנטו לכל חלופה מותרת, מדורג מהמשתלם ביותר.
- **נציג:** פנייה כשחסר נתון. בינתיים מוצג הנטו של היום, ואחרי התשובה השיחה ממשיכה מאותה נקודה.
- **תלוש שכר:** פרטים מזהים מושחרים לפני שהטקסט מגיע למודל, וכל ערך נבדק מול שורת התלוש שהמודל ציטט. העובד מאשר כל ערך לפני שהוא נשמר.
- **אבטחה:** כניסה עם טוקן חתום, וכל שיחה נגישה רק עם הטוקן שלה. המצב נשמר גם אחרי רענון של הדף.

### מגבלות
- **הכניסה היא לדמו:** הקודים מוגדרים בקובץ. מסך הנציג פתוח לכל מי שיש לו את המפתח המשותף, בלי משתמש לכל נציג.
- **שיטת הנטו היא לפי קובץ הכללים:** חודשית (לא מצטברת), לוחות 2025, והפישוטים שמוגדרים שם, כמו הפרשות על כל הברוטו. התוצאה היא נטו משוער להשוואה, לא תלוש רשמי.
- **רק רכבים מהקטלוג:** רכב מחוץ לקטלוג עובר לנציג, כי אין לו נתונים לחישוב. אם העובד יודע סכום השתתפות שסוכם לו, הסכום עובר לנציג לאישור.
- **השיחה תלויה בזמינות ספק המודל.** יש גיבוי בין ספקים, ואפשר להפעיל מצב בלי מודל (`LLM_FALLBACK=rules`). החישובים עצמם לא תלויים במודל.
- **תלוש סרוק:** נקרא מתמונה, ורק בהסכמת העובד. תמונה אי אפשר להשחיר, ולכן העובד מתבקש להסכים לפני שהיא נשלחת.


### מה נדרש לפיילוט
- **כניסה ארגונית (SSO)** במקום קודי הדמו, ומשתמש אישי לכל נציג, עם תיעוד של מי ענה מה.
- **חיבור למערכת השכר ומשאבי האנוש:** נתוני העובד, הרכב הנוכחי וההשתתפות ייטענו משם ולא מהאקסל.
- **נתונים אמיתיים:** קובץ כללים, קטלוג ועיסוקים אמיתיים, בלי שינוי קוד, דרך `STRAUSS_DATA_DIR`. אישור של מחלקת השכר לשיטת החישוב, או החלפה במנוע השכר של החברה.
- **תשתית:** אחסון בתשלום שלא נרדם, ניטור, וגיבוי של בסיס הנתונים.
- **פרטיות:** סקירת פרטיות ומדיניות שמירת שיחות. הסכם עיבוד נתונים עם ספק המודל, או מודל שרץ בתשתית של החברה.
- **בדיקות:** אוסף שאלות אמיתיות של עובדים, כדי לבדוק את איכות השיחה לאורך זמן.
